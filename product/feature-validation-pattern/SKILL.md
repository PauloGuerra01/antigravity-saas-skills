# Feature Validation Pattern

## Purpose

Ensure that new features are validated before committing significant development effort.

Feature validation helps determine whether a proposed feature delivers real value to users.

Validating ideas early reduces wasted development time and improves product focus.

---

# When to Use This Skill

Use this skill whenever:

- evaluating new feature ideas
- prioritizing product roadmap items
- deciding whether to invest development resources
- testing assumptions about user needs

Validation should occur before large implementation efforts.

---

# Hypothesis Definition

Feature validation begins with a clear hypothesis.

A hypothesis should define:

the user problem  
the proposed solution  
the expected outcome

Clear hypotheses guide validation efforts.

---

# Validation Methods

Several methods can be used to validate features.

Examples include:

user interviews  
prototype testing  
landing page experiments  
limited feature rollouts

These approaches help gather real user feedback.

---

# Minimum Viable Implementation

Features should often be implemented in a minimal form.

Examples include:

simplified versions of functionality  
limited-access beta features  
experimental releases

This allows early validation without full investment.

---

# Measuring Results

Feature validation requires measurable outcomes.

Examples include:

feature adoption rates  
user feedback  
conversion metrics

These metrics help determine whether the feature provides value.

---

# Iterative Improvement

Based on validation results, features may be:

expanded  
modified  
or discarded

Iterative development ensures the product evolves based on real user needs.

---

# Risk Reduction

Validation reduces product risk by ensuring development efforts focus on meaningful improvements.

Testing assumptions before large implementations improves long-term product success.

---

# Output Format

When applying this skill, the agent must produce:

1. Feature hypothesis definition  
2. Validation method selection  
3. Minimal implementation plan  
4. Measurement metrics  
5. Iteration strategy
