# Frontend Architecture Pattern

## Purpose

Define a production-grade architecture for SaaS frontend applications.

This skill ensures that frontend systems generated by AI agents follow a structured architecture that is scalable, maintainable, and consistent with modern SaaS engineering practices.

The architecture enforces:

* modular feature-based organization
* clear separation between UI and business logic
* predictable data flow
* reusable UI components
* centralized API communication

Agents must avoid generating ad-hoc frontend structures and instead follow a standardized architectural model.

---

# When to Use This Skill

Use this skill whenever:

* creating a new frontend application
* structuring a React or Next.js project
* organizing the frontend codebase
* introducing new feature modules
* refactoring frontend architecture

This skill defines the **baseline architecture** for all frontend systems.

Other frontend skills assume this architectural structure is already established.

# Core Architectural Principles

## 1. Feature-Based Architecture

Frontend systems must be organized around **domain features**, not file types.

Avoid structures like:

components/
hooks/
services/

Instead prefer:

features/
authentication/
dashboard/
billing/
settings/

Each feature should contain its own:

* components
* hooks
* services
* types

Example:

features/dashboard/

components/
hooks/
services/
types/

This structure improves maintainability and reduces cross-module dependencies.

---

## 2. Layered Frontend Architecture

Frontend systems must follow a clear logical layer separation.

Architecture flow:

UI Components  
↓  
Feature Hooks / Domain Logic  
↓  
Service Layer / API Clients  
↓  
Backend APIs

Responsibilities:

UI Components  
Responsible for rendering and user interaction.

Hooks / Domain Logic  
Responsible for state management and business logic.

Service Layer  
Responsible for communicating with backend APIs.

This separation ensures predictable and testable systems.

---

## 3. Predictable Data Flow

Frontend data should follow a structured flow.

API  
↓  
Service  
↓  
Hook  
↓  
Component

Example:

dashboard-api.ts  
↓  
useDashboardMetrics.ts  
↓  
DashboardMetricsCard.tsx

Components must **never fetch data directly**.

---

## 4. Strong Type Safety

All frontend code must use **TypeScript**.

Shared types should be defined in dedicated type files.

Examples:

* user.types.ts
* billing.types.ts
* api.types.ts

Types should be shared across:

* services
* hooks
* components

This ensures consistent data models across the frontend.

---

# Implementation Guidelines

## Keep UI Components Lightweight

Components should focus primarily on rendering.

Avoid embedding business logic inside UI components.

Incorrect approach:

component handles API request  
component processes business logic  
component renders UI

Correct approach:

component calls hook  
hook handles logic  
service handles API

---

## Feature Isolation

Each feature module should be self-contained.

Example:

features/dashboard  
features/billing

Features should not directly depend on internal files from other features.

Shared utilities should live in:

hooks/  
services/  
types/

---

## Centralized API Communication

All API communication must go through a service layer.

Example:

services/api-client.ts

Or feature-specific services:

features/billing/services/billing-api.ts

This allows consistent authentication handling and error management.

---

# Anti-Patterns

Agents must avoid the following patterns.

## Fat Components

Components that handle:

* API calls
* business logic
* complex state management

This creates tightly coupled systems.

---

## Direct API Calls in Components

Avoid patterns like:

useEffect(() => {
fetch("/api/users")
})

Instead prefer hooks that encapsulate the data logic.

---

## Excessive Global State

Do not place all application state in global stores.

Prefer:

* hook state
* feature-level state
* server-state libraries

---

# Expected AI Behavior

When generating frontend systems, the AI agent should:

* organize code by feature modules
* separate UI, logic, and API layers
* keep components lightweight
* centralize API communication
* maintain strong TypeScript typing

Example feature structure:

features/dashboard/

components/
DashboardHeader.tsx
MetricsCard.tsx

hooks/
useDashboardMetrics.ts

services/
dashboard-api.ts

types/
dashboard.types.ts
