# Component Design Pattern

## Purpose

Define a consistent approach for designing React components in SaaS frontend systems.

This skill ensures that AI agents generate components that are:

* reusable
* composable
* predictable
* maintainable
* easy to test

The goal is to prevent the creation of **monolithic UI components** and instead promote small, focused, composable components that follow modern React architecture practices.

---

# When to Use This Skill

Use this skill whenever:

* creating new React components
* building UI features
* designing reusable UI elements
* structuring component hierarchies
* refactoring frontend UI code

This skill should be applied to **all React components** generated by AI agents.

---

# Core Architectural Principles

## 1. Single Responsibility Components

Each component should have a **single responsibility**.

A component should focus on one role:

* display UI
* compose layout
* orchestrate smaller components

Avoid components that handle multiple responsibilities.

Bad example:

Component that:

* fetches data
* handles business logic
* renders complex UI
* manages multiple states

Preferred approach:

Separate responsibilities across:

* hooks
* services
* components

---

## 2. Presentation vs Container Components

Components should follow the **presentation/container separation** pattern.

### Presentation Components

Presentation components focus on rendering UI.

Characteristics:

* receive data via props
* contain minimal logic
* reusable across features
* no direct API calls
