# Feature Definition Pattern

## Purpose

Ensure that product features are clearly defined before implementation.

Clear feature definitions help align engineering efforts with product goals and user needs.

Well-defined features reduce ambiguity and improve development efficiency.

---

# When to Use This Skill

Use this skill whenever:

- planning new product features
- defining development tasks
- translating product ideas into engineering work
- preparing development roadmaps

Every feature should have a clear definition before implementation begins.

---

# Feature Description

Each feature should include a concise description explaining its purpose.

The description should answer:

what the feature does  
who benefits from it  
why it is valuable

A clear description helps teams understand the intent behind the feature.

---

# User Perspective

Features should be described from the user's perspective.

Example format:

"As a user, I want to..."

This approach focuses development on solving real user problems.

---

# Functional Scope

Feature definitions must describe the expected functionality.

Examples include:

core user actions  
system responses  
visible user interface elements

Defining scope prevents feature creep and unclear expectations.

---

# Success Criteria

Each feature should define measurable success criteria.

Examples include:

feature usage metrics  
performance improvements  
user satisfaction indicators

Success criteria help evaluate whether the feature achieves its goal.

---

# Dependencies

Feature definitions should identify dependencies.

Examples include:

required APIs  
database changes  
external integrations

Understanding dependencies improves development planning.

---

# Implementation Boundaries

Feature definitions should clarify what is included and excluded.

Explicit boundaries prevent misunderstandings during implementation.

---

# Documentation

Feature documentation should remain accessible for the development team.

Well-documented features improve collaboration between product and engineering.

---

# Output Format

When applying this skill, the agent must produce:

1. Feature description  
2. User perspective statement  
3. Functional scope definition  
4. Success criteria  
5. Dependency identification
