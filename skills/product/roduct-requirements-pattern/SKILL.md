# Product Requirements Pattern

## Purpose

Ensure that product ideas are translated into clear and structured requirements before implementation.

Well-defined requirements help engineering teams understand what needs to be built and why it matters.

Clear requirements reduce ambiguity and improve development efficiency.

---

# When to Use This Skill

Use this skill whenever:

- defining new product capabilities
- planning development milestones
- documenting product ideas
- preparing development tasks

Structured requirements improve collaboration between product and engineering.

---

# Problem Definition

Each requirement should begin with a clear description of the problem being solved.

The problem definition should explain:

what challenge users face  
why the problem matters  
how the product intends to solve it

Understanding the problem ensures meaningful feature development.

---

# Product Goals

Requirements should align with broader product goals.

Examples include:

improving user experience  
increasing engagement  
enabling new capabilities

Clear goals help guide design and implementation decisions.

---

# Functional Requirements

Functional requirements describe what the system must do.

Examples include:

user actions supported by the system  
system responses to those actions  
expected system behavior

These requirements define the core functionality.

---

# Non-Functional Requirements

Non-functional requirements define system characteristics.

Examples include:

performance expectations  
security requirements  
availability targets

These requirements ensure the system meets operational standards.

---

# Acceptance Criteria

Each requirement should include acceptance criteria.

Acceptance criteria define conditions that must be met for the feature to be considered complete.

Clear criteria help validate successful implementation.

---

# Traceability

Requirements should be traceable to development work.

Examples include:

task references  
feature identifiers  
documentation links

Traceability improves project management and accountability.

---

# Documentation

Requirements should remain accessible and updated throughout the product lifecycle.

Documentation ensures that teams share a consistent understanding of system behavior.

---

# Output Format

When applying this skill, the agent must produce:

1. Problem definition  
2. Product goals  
3. Functional requirements  
4. Non-functional requirements  
5. Acceptance criteria
